A. 지리적 중복 저장소(GRS): 이 옵션은 요구 사항을 충족합니다. 기본 위치에서 최소 400마일 떨어진 보조 지역에 데이터를 복제합니다. 보조 지역의 데이터에 대한 읽기 액세스를 제공하여 기본 위치와 보조 위치 모두에서 읽을 수 있습니다. B. 읽기 전용 지리적 중복 저장소: 보조 지역의 데이터에 대한 읽기 액세스를 제공하지만 기본 위치와 보조 위치 모두에서 읽을 수 있어야 한다는 요구 사항을 충족하지 않습니다. 따라서 이 시나리오에 가장 적합하지 않습니다. C. 영역 중복 저장소: 이 중복 옵션은 고가용성을 위해 지역 내의 여러 가용성 영역에 데이터를 복제하도록 설계되었지만 별도의 지리적 위치 요구 사항을 충족하지 않습니다. D. 로컬 중복 저장소: 이 옵션은 동일한 지역 내에서 데이터를 복제하지만 별도의 지리적 위치에는 복제하지 않으므로 요구 사항을 충족하지 않습니다. 따라서 정답은 A. 지리적 중복 저장소(GRS)입니다.

In Azure terminology, Read-Access Geo-Redundant Storage (RA-GRS) is sometimes referred to as "Read-Only Geo-Redundant Storage" because: Secondary Region Access is Read-Only: In RA-GRS, data replicated to the secondary region is accessible but only in read-only mode. This means users cannot modify the data in the secondary location—they can only read it. Write operations are still limited to the primary location. Distinction from Full Read-Write Access: The term "read-only" emphasizes that while you can access data in the secondary region, it’s not a fully writable, independent copy. Changes must still originate in the primary location, and then they’re asynchronously replicated to the secondary. Summary: So, "read-only" simply clarifies that while the secondary location provides access for reading, it’s not intended for active data modification, thus helping maintain data integrity across regions. Correct Answer: B. Read-Only Geo-Redundant Storage (RA-GRS)

Selected Answer: B
RA-GRS allows Read-Only Access to the secondary region without the need for failure in the primary region. However, because data is replicated asynchronously from the primary to the secondary region, the secondary region is typically behind the primary region in terms of write operations. If a disaster were to strike the primary region, it's likely that some data would be lost. The interval between the most recent writes to the primary region and the last write to the secondary region is known as the recovery point objective (RPO). The RPO indicates the point in time to which data can be recovered. The Azure Storage platform typically has an RPO of less than 15 minutes, although there's currently no SLA on how long it takes to replicate data to the secondary region. And note that Azure Files does not support read-access geo-redundant storage (RA-GRS) or read-access geo-zone-redundant storage (RA-GZRS).
