N,Y,N The "permissions" property of the custom RBAC role "Role1" specifies a list of actions that the users assigned this role are allowed to perform within the specified "assignableScopes". The actions in the "notAction" list are explicitly excluded from the allowed actions, meaning that users with this role cannot perform these actions. Based on this information, we can conclude that: Users assigned Role1 cannot assign Role1 to other users because the "Microsoft.Authorization/*/Write" action is in the "notAction" list. Users assigned Role1 can deploy new virtual machines because the "Microsoft.Resources/deployments/*" action is in the "actions" list. Users assigned Role1 cannot set a static IP address on a virtual machine because there is no mention of the action "Microsoft.Network/networkinterfaces/*/write" or similar in the "actions" or "notAction" list.
