틀렸습니다. NSG는 상태를 저장한다는 점을 기억하세요. Ping 요청(기술적으로는 ICMP 에코 요청)이 NSG를 통과하면 NSG는 이를 상태 테이블에 등록합니다. 그런 다음 VM2에서 Pong(ICMP 에코 응답)이 나타나면 NSG는 수신된 Ping과 일치하는 Ping을 확인하여 통과를 허용합니다. VM1이 먼저 시작하지 않고 VM2가 VM1에 ICMP 에코 응답을 보내면, 서브넷 수준 NSG는 상태 테이블에 일치하는 항목이 없으므로 이를 차단합니다. 또한, 정답은 VM1이 VM2에게만 ping을 보낼 수 있도록 허용하는 것이지, 그 반대는 아닙니다. VM2가 VM1에게 ping을 보낼 수 있도록 하려면 상호 규칙이 필요합니다.

Lionred
2021-12-12 10:44
That is not correct. Remember NSGs are stateful, when the Ping request (technically ICMP Echo request) is passed through NSG, NSG registers it on its state table, then when Pong (ICMP Echo reply) shows up from VM2, NSG will find it matches the incoming Ping hence will allow it to go through. If VM2 sends an ICMP Echo reply to VM1 without VM1 initiating it first, subnet-level NSG will simply block it since there is no matching entry on its state table. Moreover, the correct answer will only allow VM1 to ping VM2, not the other way around. If we want VM2 to be able ping VM1, we will then need a reciprocal rule in place.
