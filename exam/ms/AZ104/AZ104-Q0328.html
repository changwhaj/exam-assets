정답: C 사이트 간 VPN 게이트웨이 연결은 IPsec/IKE(IKEv1 또는 IKEv2) VPN 터널을 통해 온프레미스 네트워크를 Azure 가상 네트워크에 연결하는 데 사용할 수 있습니다. 이러한 연결에는 외부 공용 IP 주소가 할당된 온프레미스에 위치한 VPN 장치(VPN 게이트웨이)가 필요합니다. A: 애플리케이션 게이트웨이는 http, https 및 웹소켓용이며 SMB용이 아닙니다. B: 애플리케이션 프록시는 온프레미스 웹 애플리케이션에도 액세스하는 데 사용되며 SMB용이 아닙니다. 애플리케이션 프록시는 사용자가 원격 클라이언트에서 온프레미스 웹 애플리케이션에 액세스할 수 있도록 하는 Azure AD의 기능입니다. 참고: https://docs.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-howto-site-to-site-resource-manager-portal

선택한 답변: C
SMB(서버 메시지 블록)는 네트워크 파일 공유에 액세스하는 데 사용되는 프로토콜을 지정합니다. SMB는 일반적으로 Windows 환경에서 파일 공유에 사용되며 연결이 작동하려면 액세스가 필요한 특정 포트(TCP 445 및 기타)를 통해 작동합니다. Azure 가상 네트워크와 온-프레미스 네트워크 간에 VPN을 설정하면 webapp1이 SMB 공유를 포함한 온-프레미스 리소스와 통신할 수 있습니다. 그러나 Azure Web Apps는 일반적으로 보안상의 이유로 SMB 포트를 차단하기 때문에 Azure Web App에서 SMB 공유에 액세스하는 것은 까다로울 수 있습니다. 이 문제를 해결하려면 Azure Virtual Machines 사용: SMB 공유에 액세스하고 중개자 역할을 할 수 있는 VM을 Azure VNet에 배포하거나 Azure File Sync와 같은 다른 방법을 사용해야 할 수 있습니다. 온-프레미스 파일 공유를 Azure Files와 동기화하면 웹 앱에서 액세스할 수 있습니다.

Selected Answer: C
SMB (Server Message Block) specifies the protocol used for accessing network file shares. SMB is commonly used for file sharing in Windows environments, and it operates over specific ports (TCP 445 and others) that need to be accessible for the connection to work. When you set up a VPN between your Azure virtual network and your on-premises network, it allows webapp1 to communicate with on-premises resources, including SMB shares. However, accessing SMB shares from an Azure Web App can be tricky because Azure Web Apps typically block SMB ports for security reasons.To work around this, you might need to use a different approach, such as Using Azure Virtual Machines: Deploy a VM in your Azure VNet that can access the SMB share and act as an intermediary. Or Azure File Sync - Sync your on-premises file shares with Azure Files, which can then be accessed by your web app.
