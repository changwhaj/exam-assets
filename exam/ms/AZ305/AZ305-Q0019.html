상자 1: 2 -
각 Azure AD 테넌트에 대한 하나의 관리 그룹
Azure 관리 그룹은 구독보다 높은 수준의 범위를 제공합니다.
관리 그룹 내의 모든 구독은 관리 그룹에 적용된 조건을 자동으로 상속합니다.

청사진 정의를 관리 그룹에 할당하면 할당 개체가 관리 그룹에 존재합니다. 아티팩트 배포는 여전히 구독을 대상으로 합니다.

HOTSPOT -
Your company has the divisions shown in the following table.

You plan to deploy a custom application to each subscription. The application will contain the following:
✑ A resource group
✑ An Azure web app
✑ Custom role assignments
✑ An Azure Cosmos DB account
You need to use Azure Blueprints to deploy the application to each subscription.
What is the minimum number of objects required to deploy the application? To answer, select the appropriate options in the answer area.
NOTE: Each correct selection is worth one point.
Hot Area:

Show Suggested Answer Hide Answer
Suggested Answer:
Box 1: 2 -
One management group for each Azure AD tenant
Azure management groups provide a level of scope above subscriptions.
All subscriptions within a management group automatically inherit the conditions applied to the management group.
All subscriptions within a single management group must trust the same Azure Active Directory tenant.

Box 2: 1 -
One single blueprint definition can be assigned to different existing management groups or subscriptions.
When creating a blueprint definition, you'll define where the blueprint is saved. Blueprints can be saved to a management group or subscription that you have
Contributor access to. If the location is a management group, the blueprint is available to assign to any child subscription of that management group.

Box 3: 2 -

Blueprint assignment -
Each Published Version of a blueprint can be assigned (with a max name length of 90 characters) to an existing management group or subscription.
Assigning a blueprint definition to a management group means the assignment object exists at the management group. The deployment of artifacts still targets a subscription.

The answer is correct: A single management group can be used for multiple Azure AD tenants, but it is important to note that management groups only apply to resources within the same tenant. If you have resources across multiple tenants that you want to manage together, you would need to use a management group for each tenant. A single blueprint definition can be used for multiple Azure AD tenants, but it would need to be assigned to each tenant individually. The blueprint definition is a JSON file that defines the structure and configuration of the resources you want to deploy. It can be created and managed in the Azure portal, Azure Resource Manager templates, or Azure CLI and it can be used across multiple tenants. It's also worth noting that Azure Blueprints are scoped to the management group level, so you would need to assign the blueprint to each management group that contains resources across multiple tenants.
