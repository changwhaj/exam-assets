In Retrieval Augmented Generation (RAG), chunking splits large documents into smaller, meaningful pieces before generating embeddings. This is done to: - Ensure that retrieved chunks are contextually relevant to the user query - Improve the accuracy and quality of responses from the generative model - Avoid situations where a single embedding for a large document loses fine-grained context Other options are incorrect: A. Database storage limitations → Chunking is not primarily for storage. B. Avoiding embeddings → Chunking actually requires creating embeddings for each chunk. D. Decrease cost of storage → Not the main purpose; it’s about contextual relevancy.
