  • A. Amazon CloudWatch 메트릭을 데이터 소스로 사용하여 FM 전반에 걸친 토큰 사용 추세 및 사용 패턴을 보여주는 사용자 지정 Amazon QuickSight 대시보드를 생성합니다.
  • B. Amazon CloudWatch Logs Insights를 사용하여 Amazon Bedrock 호출 로그를 분석하여 토큰 소비 패턴 및 애플리케이션별 사용 내역을 파악합니다. 사용량이 많은 시나리오를 식별하기 위한 사용자 지정 쿼리를 생성합니다. 대시보드에 로그 위젯을 추가하여 지속적인 모니터링을 지원합니다. 가장 많은 표를 받은
  • C. Amazon Bedrock 토큰 및 호출 CloudWatch 지표를 결합하는 사용자 지정 Amazon CloudWatch 대시보드를 생성합니다. 토큰 사용량 임계값을 모니터링하도록 CloudWatch 알람을 설정합니다. 가장 많은 표를 받은
  • D. Amazon Bedrock의 ETL 제로 통합과 Amazon Managed Grafana를 사용하여 회사 전체 FM에 걸쳐 토큰 사용 추세 및 패턴을 보여주는 대시보드를 생성합니다.

Exam question from Amazon's AWS Certified Generative AI Developer - Professional AIP-C01
Question #: 66
Topic #: 1

A company deploys multiple Amazon Bedrock based generative AI (GenAI) applications across multiple business units for customer service, content generation, and document analysis. Some applications show unpredictable token consumption patterns. The company requires a comprehensive observability solution that provides real-time visibility into token usage patterns across multiple models. The observability solution must support custom dashboards for multiple stakeholder groups and provide alerting capabilities for token consumption across all the foundational models that the company's applications use.
Which combination of solutions will meet these requirements with the LEAST operational overhead? (Choose two.)

  • A. Use Amazon CloudWatch metrics as data sources to create custom Amazon QuickSight dashboards that show token usage trends and usage patterns across FMs.
  • B. Use Amazon CloudWatch Logs Insights to analyze Amazon Bedrock invocation logs for token consumption patterns and usage attribution by application. Create custom queries to identify high-usage scenarios. Add log widgets to dashboards to enable continuous monitoring. Most Voted
  • C. Create custom Amazon CloudWatch dashboards that combine native Amazon Bedrock token and invocation CloudWatch metrics. Set up CloudWatch alarms to monitor token usage thresholds. Most Voted
  • D. Create dashboards that show token usage trends and patterns across the company's FMs by using an Amazon Bedrock zero-ETL integration with Amazon Managed Grafana.
  • E. Implement Amazon EventBridge rules to capture Amazon Bedrock model invocation events. Route token usage data to an Amazon Data Firehose delivery stream that targets Amazon OpenSearch Serverless. Use OpenSearch dashboards to analyze usage patterns.

Option-C: is the cleanest way to get near real-time visibility and alerting with the least overhead. Amazon Bedrock publishes native CloudWatch runtime metrics such as InputTokenCount and OutputTokenCount, and can graph them in CloudWatch and set alarms on thresholds. Option-B: complements that by giving deeper usage-pattern analysis and attribution by application from Bedrock model invocation logs in CloudWatch Logs. Bedrock invocation logging can send request/response data and metadata to CloudWatch Logs, and CloudWatch Logs Insights can query those logs and its results can be added as log widgets to dashboards.
