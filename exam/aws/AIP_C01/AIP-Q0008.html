문제 번호: 8
주제 번호: 1

한 회사가 Amazon Bedrock을 사용하는 AWS 애플리케이션 계정에서 생성형 AI(GenAI) 기반 요약 애플리케이션을 운영하고 있습니다. 애플리케이션 아키텍처에는 프라이빗 VPC 서브넷에 연결된 AWS Lambda 함수로 요청을 전달하는 Amazon API Gateway REST API가 포함되어 있습니다. 이 애플리케이션은 회사가 중앙 집중식 데이터 스토리지 계정의 관리형 데이터 레이크에 저장한 민감한 고객 기록을 요약합니다. 회사는 데이터 스토리지 계정에 Amazon S3, Amazon Athena 및 AWS Glue를 활성화했습니다.
회사는 애플리케이션이 Amazon Bedrock에 대한 호출을 할 때 회사 애플리케이션 VPC와 Amazon Bedrock 간의 프라이빗 연결만 사용해야 합니다. 또한 회사의 데이터 레이크는 회사 AWS 계정 전체에서 세분화된 열 수준 액세스를 제공해야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇일까요?

  • A. 애플리케이션 계정에서 Amazon Bedrock 런타임용 VPC 인터페이스 엔드포인트를 생성합니다. Lambda 함수는 프라이빗 서브넷에서 실행합니다. 추론 및 데이터 플레인 정책에 IAM 조건을 사용하여 승인된 엔드포인트 및 역할에 대한 호출만 허용합니다. 데이터 스토리지 계정에서 AWS Lake Formation LF 태그 기반 액세스 제어를 사용하여 테이블 및 열 수준의 계정 간 권한 부여를 생성합니다. 가장 많은 표를 받은
  • B. Lambda 함수를 프라이빗 서브넷에서 실행합니다. Amazon Bedrock 및 데이터 레이크에 액세스할 수 있도록 NAT 게이트웨이를 구성합니다. S3 버킷 정책 및 ACL을 사용하여 권한을 관리합니다. AWS CloudTrail 로그를 Amazon S3로 내보내 주간 검토를 수행합니다.
  • C. 애플리케이션 계정에 Amazon S3 전용 게이트웨이 엔드포인트를 생성합니다. 공용 엔드포인트를 통해 Amazon Bedrock을 호출합니다. AWS Lake Formation에서 데이터베이스 수준 권한을 사용하여 데이터 액세스를 관리합니다. AWS CloudTrail 로그를 Amazon CloudWatch Logs로 스트리밍합니다. 메트릭 필터 또는 경보를 설정하지 마십시오.
  • D. VPC 엔드포인트를 사용하여 애플리케이션 계정에서 Amazon Bedrock 및 Amazon S3에 액세스할 수 있도록 합니다. 데이터 레이크 액세스 관리에는 IAM 경로 기반 정책만 사용합니다. AWS CloudTrail 로그를 Amazon CloudWatch Logs로 전송합니다. 주기적으로 대시보드를 생성하고, 설정 시간을 줄이기 위해 리전 간 읽기에 대한 퍼블릭 폴백을 허용합니다.

Exam question from Amazon's AWS Certified Generative AI Developer - Professional AIP-C01
Question #: 8
Topic #: 1

A company runs a generative AI (GenAI)-powered summarization application in an application AWS account that uses Amazon Bedrock. The application architecture includes an Amazon API Gateway REST API that forwards requests to AWS Lambda functions that are attached to private VPC subnets. The application summarizes sensitive customer records that the company stores in a governed data lake in a centralized data storage account. The company has enabled Amazon S3, Amazon Athena, and AWS Glue in the data storage account.
The company must ensure that calls that the application makes to Amazon Bedrock use only private connectivity between the company's application VPC and Amazon Bedrock. The company's data lake must provide fine-grained column-level access across the company's AWS accounts.
Which solution will meet these requirements?

  • A. In the application account, create interface VPC endpoints for Amazon Bedrock runtimes. Run Lambda functions in private subnets. Use IAM conditions on inference and data-plane policies to allow calls only to approved endpoints and roles. In the data storage account, use AWS Lake Formation LF-tag-based access control to create table and column-level cross-account grants. Most Voted
  • B. Run Lambda functions in private subnets. Configure a NAT gateway to provide access to Amazon Bedrock and the data lake. Use S3 bucket policies and ACLs to manage permissions. Export AWS CloudTrail logs to Amazon S3 to perform weekly reviews.
  • C. Create a gateway endpoint only for Amazon S3 in the application account. Invoke Amazon Bedrock through public endpoints. Use database-level grants in AWS Lake Formation to manage data access. Stream AWS CloudTrail logs to Amazon CloudWatch Logs. Do not set up metric filters or alarms.
  • D. Use VPC endpoints to provide access to Amazon Bedrock and Amazon S3 in the application account. Use only IAM path-based policies to manage data lake access. Send AWS CloudTrail logs to Amazon CloudWatch Logs. Periodically create dashboards and allow public fallback for cross-Region reads to reduce setup time.
