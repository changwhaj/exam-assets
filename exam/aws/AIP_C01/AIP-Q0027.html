한 전자상거래 회사가 Amazon Bedrock을 사용하여 생성형 AI(GenAI) 애플리케이션을 구축하고 있습니다. 이 애플리케이션은 AWS Step Functions를 활용하여 여러 에이전트로 구성된 워크플로우를 오케스트레이션하고 상세한 제품 설명을 생성합니다. 워크플로우는 설명 생성기, 기술 사양 검증기, 브랜드 보이스 일관성 검사기라는 세 가지 순차적인 단계로 구성됩니다. 각 단계는 중간 추론 과정과 출력을 생성하여 다음 단계로 전달합니다. 애플리케이션은 처리 과정과 출력 저장을 위해 Amazon S3 버킷을 사용합니다.
테스트 중 Step Functions 단계 간 출력 크기가 256KB 할당량을 자주 초과하여 워크플로우 오류가 발생하는 것을 발견했습니다.
GenAI 개발자는 Step Functions의 256KB 할당량을 효율적으로 처리하고 워크플로우의 가시성을 유지할 수 있도록 애플리케이션 아키텍처를 수정해야 합니다. 수정된 아키텍처는 기존의 다중 에이전트 추론 및 실행(ReAct) 패턴을 유지해야 합니다.
이러한 요구 사항을 충족하면서 운영 오버헤드를 최소화하는 솔루션은 무엇일까요?

  • A. 중간 출력값을 Amazon DynamoDB에 저장합니다. 상태 간에는 참조만 전달합니다. 각 에이전트의 처리 단계에 필요한 경우 DynamoDB에서 전체 데이터를 검색하는 Map 상태를 생성합니다.
  • B. 대용량 출력의 경우 입력 매개변수에 S3 버킷 URI를 사용하도록 Amazon Bedrock 통합을 구성합니다. 순차적 유효성 검사 워크플로를 유지하면서 에이전트 단계 간에 S3 참조를 라우팅하려면 ResultPath 필드와 ResultSelector 필드를 사용합니다. 가장 많은 표를 받은
  • C. 각 에이전트 상태로 넘어가기 전에 AWS Lambda 함수를 사용하여 출력을 256KB 미만으로 압축합니다. 각 에이전트 작업은 처리 전에 출력을 압축 해제하고 다음 상태로 전달하기 전에 결과를 다시 압축하도록 구성합니다.
  • D. 각 에이전트의 처리를 위해 별도의 Step Functions 상태 머신을 구성합니다. Amazon EventBridge를 사용하여 상태 머신 간의 실행 흐름을 조정합니다. 출력은 이벤트 데이터로 S3 참조를 사용합니다.

Exam question from Amazon's AWS Certified Generative AI Developer - Professional AIP-C01
Question #: 27
Topic #: 1

An ecommerce company is using Amazon Bedrock to build a generative AI (GenAI) application. The application uses AWS Step Functions to orchestrate a multi-agent workflow to produce detailed product descriptions. The workflow consists of three sequential states: a description generator, a technical specifications validator, and a brand voice consistency checker. Each state produces intermediate reasoning traces and outputs that are passed to the next state. The application uses an Amazon S3 bucket for process storage and to store outputs.
During testing, the company discovers that outputs between Step Functions states frequently exceed the 256 KB quota and cause workflow failures.
A GenAI Developer needs to revise the application architecture to efficiently handle the Step Functions 256 KB quota and maintain workflow observability. The revised architecture must preserve the existing multi-agent reasoning and acting (ReAct) pattern.
Which solution will meet these requirements with the LEAST operational overhead?

  • A. Store intermediate outputs in Amazon DynamoDB. Pass only references between states. Create a Map state that retrieves the complete data from DynamoDB when required for each agent's processing step.
  • B. Configure an Amazon Bedrock integration to use the S3 bucket URI in the input parameter for large outputs. Use the ResultPath field and the ResultSelector field to route S3 references between the agent steps while maintaining the sequential validation workflow. Most Voted
  • C. Use AWS Lambda functions to compress outputs to less than 256 KB before each agent state. Configure each agent task to decompress the outputs before processing and to compress results before passing them to the next state.
  • D. Configure a separate Step Functions state machine to handle each agent's processing. Use Amazon EventBridge to coordinate the execution flow between state machines. Use S3 references for the outputs as event data.
