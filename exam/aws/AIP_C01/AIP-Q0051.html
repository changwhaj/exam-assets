이 회사는 중복 모델 호출을 줄이는 솔루션을 원합니다. 또한, 의미적으로 동일한 질문에는 일관된 답변이 제공되어야 하며, 지연 시간도 최소화해야 합니다.
이러한 요구 사항을 모두 충족하는 솔루션은 무엇일까요?

  • A. Amazon DynamoDB Accelerator(DAX) 클러스터를 인메모리 캐시로 배포합니다. 쿼리 텍스트를 파티션 키로, 모델 응답 텍스트를 정렬 키로 지정합니다. LIKE 연산자를 사용하는 필터 표현식을 이용하여 캐시를 쿼리합니다.
  • B. Amazon Bedrock을 사용하여 고객 쿼리에서 임베딩을 생성합니다. Amazon MemoryDB for Valkey를 사용하여 벡터 임베딩 및 모델 응답의 해시 세트를 저장합니다. RANGE 쿼리를 사용하여 유사한 쿼리와 해당 응답을 찾습니다.
  • C. k-최근접 이웃(k-NN) 기능을 갖춘 Amazon OpenSearch 서비스를 배포하여 질의-응답 텍스트 쌍을 저장합니다. 근사 k-NN 기법을 사용하여 유사한 질의와 해당 응답을 찾습니다. 가장 많은 표를 받은
  • D. Amazon DynamoDB를 사용하여 정규화된 쿼리 텍스트에 대한 전역 보조 인덱스를 생성함으로써 캐싱 솔루션을 구축합니다. 들어오는 쿼리에 어간 추출을 적용합니다. 캐시된 고객 쿼리의 인덱스를 조회합니다.

Exam question from Amazon's AWS Certified Generative AI Developer - Professional AIP-C01
Question #: 51
Topic #: 1

A company uses Amazon Bedrock to develop an AI assistant to provide customer support. Analysis shows that 40% of customer queries use varied phrasing or wording to ask the same questions.
The company wants a solution to reduce redundant model calls. The solution must ensure that semantically equivalent questions receive consistent answers. The solution must ensure low latency.
Which solution will meet these requirements?

  • A. Deploy an Amazon DynamoDB Accelerator (DAX) cluster as an in-memory cache. Specify the query text as the partition key and the model response text as the sort key. Query the cache by using a filter expression with the LIKE operator.
  • B. Use Amazon Bedrock to generate embeddings from customer queries. Use Amazon MemoryDB for Valkey to store hash sets of vector embeddings and model responses. Use a RANGE query to find similar queries and their responses.
  • C. Deploy Amazon OpenSearch Service that has k-nearest neighbor (k-NN) capabilities to store query-response text pairs. Use an approximate k-NN technique to find similar queries and their responses. Most Voted
  • D. Create a caching solution by using Amazon DynamoDB to create a global secondary index on the normalized query text. Apply stemming to incoming queries. Query the index of cached customer queries.

The problem is about semantically equivalent questions with different wording. Vector similarity search is built for that. You can generate embeddings for incoming queries and retrieve the most similar cached past query/response, which helps return consistent answers for equivalent questions. Approximate k-NN is designed for low-latency nearest-neighbor retrieval at scale
