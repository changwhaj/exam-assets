The communication from the vending machines to the application happens over HTTPS.
The company is planning to use an AWS Global Accelerator accelerator and configure static IP addresses of the accelerator in the vending machines for application endpoint access. The application must be accessible only through the accelerator and not through a direct connection over the internet to the ALB endpoint.

The requirement here is that the application must be accessible only through the Global Accelerator, and not via a direct connection over the internet to the ALB endpoint. Hence, the ALB should be placed in a private subnet and should be configured such that only traffic coming from the Global Accelerator can reach the ALB. Option A: This won't work because we're allowing inbound traffic from the internet on the ALB listener port. We need to restrict the traffic to the ALB only from the Global Accelerator's IP addresses. Option B: This won't work for the same reason as option A - we're allowing traffic from the entire internet to reach the ALB. Option C: This won't work because placing the ALB in a public subnet will allow it to be accessible from the internet, which we don't want. Option D: This is the correct option. Here, we're placing the ALB in a private subnet, which prevents direct access from the internet. The traffic is allowed only from the IP addresses of the Global Accelerator. Thus, access to the ALB is only possible through the Global Accelerator, fulfilling the requirement.
