문제 번호: 302
주제 번호: 1

한 개발팀이 여러 개의 Amazon S3 버킷을 중앙 집중식 저장소로 사용하고 있습니다. 전 세계 사용자들이 이러한 저장소에 대량의 파일을 업로드하고, 개발팀의 애플리케이션은 나중에 이 파일들을 처리합니다.

시스템 운영 관리자는 새로운 워크로드를 지원하기 위해 DOC-EXAMPLE-BUCKET이라는 새로운 S3 버킷을 생성했습니다. 이 새로운 S3 버킷에도 전 세계 사용자들로부터 대량의 파일이 정기적으로 업로드됩니다. 새 S3 버킷이 운영 환경에 배포된 후, 특정 지역의 업로드 성능이 기존 S3 버킷보다 낮은 문제가 발생했습니다.

시스템 운영 관리자는 이 문제를 해결하기 위해 어떤 조치를 취해야 할까요?

  • A. 새 S3 버킷에 대한 Amazon ElastiCache for Redis 클러스터를 프로비저닝합니다. 개발자가 API 호출에 사용할 수 있도록 클러스터 구성 엔드포인트를 제공합니다.
  • B. 새 S3 버킷을 새 Amazon CloudFront 배포에 추가합니다. 개발자에게 API 호출에 사용할 수 있도록 새 배포의 도메인 이름을 제공합니다.
  • C. 새 S3 버킷에 대해 S3 전송 가속을 활성화합니다. 개발자가 API 호출에서 DOC-EXAMPLE-BUCKET.s3-accelerate.amazonaws.com 엔드포인트 이름을 사용하고 있는지 확인합니다. 가장 많은 표를 받은
  • D. 새 S3 버킷에 S3 멀티파트 업로드를 사용하십시오. 개발자가 API 호출 시 DOC-EXAMPLE-BUCKETS3, [Region] amazonaws.com과 같이 지역별 S3 엔드포인트 이름을 사용하고 있는지 확인하십시오.

A team of developers is using several Amazon S3 buckets as centralized repositories. Users across the world upload large sets of files to these repositories. The development team's applications later process these files.

A SysOps administrator sets up a new S3 bucket, DOC-EXAMPLE-BUCKET, to support a new workload, The rew S3 bucket also receives regular uploads cf large sets of files from users worldwide. When the new S3 bucket is put into production, the upload performance from certain geographic areas is lower than the upload performance that the existing $3 buckets provide

What should the SysOps administrator do to remediate this issue?

  • A. Provision an Amazon ElastiCache for Redis cluster for the new S3 bucket. Provide the developers with the configuration endpoint of the cluster for use in their API calls
  • B. Add the new S3 bucket to a new Amazon CloudFront distribution. Provide the developers with the domain name of the new distribution for use in their API calls.
  • C. Enable S3 Transfer Acceleration for the new S3 bucket. Verify that the developers are using the DOC-EXAMPLE-BUCKET.s3-accelerate.amazonaws.com endpoint name in their API calls. Most Voted
  • D. Use S3 multipart upload for the new S3 bucket. Verify that the developers are using Region-specific S3 endpoint names such as DOC-EXAMPLE-BUCKETS3, [Region] amazonaws.com in their API calls.

After researching this realize that the "s3-accelerate" domain in the special URL (e.g.: "acloudguru.s3-accelerate.amazonaws.com") will resolve to the nearest edge globally, and therefore there is only one url that can be used globally to make use of transfer acceleration, albeit at some additional cost for the data transfer. Setting must be enabled on bucket though. The URLs are worth reviewing (at least they were to me) https://docs.aws.amazon.com/AmazonS3/latest/userguide/transfer-acceleration-examples.html https://www.javatpoint.com/aws-s3-transfer-acceleration etc.
