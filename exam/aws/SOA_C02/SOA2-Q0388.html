아마존 AWS 공인 시스템 운영 관리자 - 어소시에이트 시험 문제
문제 번호: 388
주제 번호: 1

한 회사가 Auto Scaling 그룹에 속한 Linux 기반 Amazon EC2 인스턴스 클러스터에 배포되는 서비스를 개발했습니다. 이 서비스는 애플리케이션 코드 오류로 인해 예기치 않게 가끔씩 장애를 일으킵니다. 회사 엔지니어링 팀은 서비스 장애의 근본 원인을 해결하는 데 몇 주가 걸릴 수 있다고 판단했습니다.

시스템 운영 관리자는 EC2 인스턴스 중 하나에서 서비스가 중단될 경우 복구를 자동화하는 솔루션을 구축해야 합니다.

이 요구 사항을 충족하는 솔루션은 무엇일까요? (두 가지를 선택하세요.)

  • A. EC2 인스턴스에 Amazon CloudWatch 에이전트를 설치합니다. CloudWatch 에이전트를 구성하여 서비스를 모니터링하도록 합니다. 서비스 상태 확인에 실패할 경우 CloudWatch 작업이 다시 시작되도록 설정합니다. 가장 많은 표를 받은
  • B. EC2 인스턴스에 태그를 지정합니다. AWS Systems Manager Session Manager를 사용하여 태그가 지정된 EC2 인스턴스에 로그인하고 서비스를 다시 시작하는 AWS Lambda 함수를 생성합니다. Lambda 함수가 5분마다 실행되도록 예약합니다.
  • C. EC2 인스턴스에 태그를 지정합니다. AWS Systems Manager State Manager를 사용하여 AWS-RunShellScript 문서를 활용하는 연결을 생성합니다. 서비스가 실행 중인지 확인하고 실행 중이 아니면 서비스를 시작하는 스크립트를 연결 명령에 포함시킵니다. 대상으로는 EC2 인스턴스 태그를 지정합니다. 연결이 5분마다 실행되도록 예약합니다. 가장 많은 표를 받은
  • D. Auto Scaling 그룹의 시작 템플릿에 지정된 EC2 사용자 데이터를 업데이트하여 5분마다 cron 스케줄에 따라 실행되는 스크립트를 포함시키십시오. 스크립트가 서비스 실행 여부를 확인하고 실행 중이 아니면 서비스를 시작하도록 구성하십시오. 업데이트된 시작 템플릿을 사용하여 Auto Scaling 그룹의 모든 EC2 인스턴스를 재배포하십시오.
  • E. 서비스가 시작 시 실행되도록 Auto Scaling 그룹의 시작 템플릿에 지정된 EC2 사용자 데이터를 업데이트합니다. 업데이트된 시작 템플릿을 사용하여 Auto Scaling 그룹의 모든 EC2 인스턴스를 다시 배포합니다.

Exam question from Amazon's AWS Certified SysOps Administrator - Associate
Question #: 388
Topic #: 1

A company has developed a service that is deployed on a fleet of Linux-based Amazon EC2 instances that are in an Auto Scaling group. The service occasionally fails unexpectedly because of an error in the application code. The company's engineering team determines that resolving the underlying cause of the service failure could take several weeks.

A SysOps administrator needs to create a solution to automate recovery if the service crashes on any of the EC2 instances.

Which solutions will meet this requirement? (Choose two.)

  • A. Install the Amazon CloudWatch agent on the EC2 instances. Configure the CloudWatch agent to monitor the service. Set the CloudWatch action to restart if the service health check fails. Most Voted
  • B. Tag the EC2 instances. Create an AWS Lambda function that uses AWS Systems Manager Session Manager to log in to the tagged EC2 instances and restart the service. Schedule the Lambda function to run every 5 minutes.
  • C. Tag the EC2 instances. Use AWS Systems Manager State Manager to create an association that uses the AWS-RunShellScript document. Configure the association command with a script that checks if the service is running and that starts the service if the service is not running. For targets, specify the EC2 instance tag. Schedule the association to run every 5 minutes. Most Voted
  • D. Update the EC2 user data that is specified in the Auto Scaling group's launch template to include a script that runs on a cron schedule every 5 minutes. Configure the script to check if the service is running and to start the service if the service is not running. Redeploy all the EC2 instances in the Auto Scaling group with the updated launch template.
  • E. Update the EC2 user data that is specified in the Auto Scaling group's launch template to ensure that the service runs during startup. Redeploy all the EC2 instances in the Auto Scaling group with the updated launch template.
