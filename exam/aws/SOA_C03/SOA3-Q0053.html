아마존 AWS 공인 클라우드 운영 엔지니어 - 어소시에이트 SOA-C03 시험 문제
문제 번호: 53
주제 번호: 1

애플리케이션이 애플리케이션 로드 밸런서(ALB) 뒤에 있는 Amazon EC2 인스턴스에서 실행됩니다. 애플리케이션이 시작된 후 로컬 캐시에 데이터가 채워지는 데 최대 2분이 소요됩니다. 애플리케이션은 시작 후 몇 초 만에 대상 그룹 상태 검사에서 정상으로 보고됩니다.
클라우드 운영 엔지니어는 일부 인스턴스가 재부팅된 후 각 인스턴스가 정상으로 보고된 직후 트래픽을 균등하게 분배받는 것을 확인했습니다. 애플리케이션 캐시가 채워지는 동안 애플리케이션은 점진적으로 증가하는 트래픽 분배를 받아야 합니다.
이 요구 사항을 충족하는 솔루션은 무엇일까요?

  • A. slow_start.duration_seconds 대상 그룹 속성을 120초로 변경합니다. 인스턴스를 재부팅하기 전에 대상 그룹에서 인스턴스를 등록 해제합니다. 인스턴스를 재부팅한 후 대상 그룹에 인스턴스를 등록합니다.
  • B. 대상 그룹에서 HealthCheckTimeoutSeconds 매개변수를 120초로 변경합니다. 인스턴스를 재부팅하기 전에 대상 그룹에서 인스턴스를 등록 해제합니다. 인스턴스를 재부팅한 후 대상 그룹에 인스턴스를 다시 등록합니다.
  • C. 상태 확인 상태를 모니터링하도록 Amazon CloudWatch 알람을 구성합니다. 상태 확인에 실패할 경우 EC2 인스턴스를 재시작하도록 알람 동작을 구성합니다. loadbalancing.algorithm.type 대상 그룹 속성을 weighted_random으로 변경합니다.
  • D. Amazon EC2 Auto Scaling 그룹을 생성합니다. 기존 EC2 인스턴스를 Auto Scaling 그룹에 연결합니다. 시작 중인 인스턴스를 대기
    (Pending Wait) 상태로 이동시키는 EC2 Auto Scaling 수명 주기 후크를 구성합니다. 로컬 캐시가 채워지면 수명 주기 후크가 완료되도록 애플리케이션을 업데이트합니다.

Exam question from Amazon's AWS Certified CloudOps Engineer - Associate SOA-C03
Question #: 53
Topic #: 1

An application runs on Amazon EC2 instances behind an Application Load Balancer (ALB). The application takes up to 2 minutes to populate a local cache after the application is started. The application reports as healthy in the target group health check a few seconds after starting.
A CloudOps engineer observes that after some of the instances are rebooted, the instances receive an equal share of the traffic immediately after each instance reports as healthy. The application needs to receive a gradually increasing share of the traffic while the application cache is populated.
Which solution will meet this requirement?

  • A. Change the slow_start.duration_seconds target group attribute to 120 seconds. Before rebooting the instances, deregister the instances from the target group. After rebooting the instances, register the instances with the target group.
  • B. Change the HealthCheckTimeoutSeconds paramotor in the target group to 120 seconds. Before rebooting the instances, deregister the instances from the target group. After rebooting the instances, register the instances with the target group.
  • C. Configure an Amazon CloudWatch alarm to monitor the health check status. Configure the action of the alarm to restart an EC2 instance if a health check fails. Change the loadbalancing.algorithm.type target group attribute to be weighted_random.
  • D. Create an Amazon EC2 Auto Scaling group. Attach the existing EC2 instances to the Auto Scaling group. Configure an EC2 Auto Scaling lifecycle hook to move starting instances to the
    Pending Wait state. Update the application to complete the lifecycle hook when the local cache has been populated.

Suggested Answer: A
