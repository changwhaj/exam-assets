2024년 9월 15일 21시 59분
이 질문의 정답은 C. Amazon FSx File Gateway입니다. Amazon FSx File Gateway는 NFS 워크로드를 AWS로 원활하게 마이그레이션하도록 설계되었습니다. 클라우드에서 완전 관리형 파일 공유에 대한 저지연 액세스를 제공하며 NFS(Network File System) 및 SMB(Server Message Block)와 같은 파일 기반 프로토콜을 지원합니다. 따라서 온프레미스 NFS 워크로드를 AWS로 마이그레이션하고 확장하는 데 이상적입니다. Amazon S3 File Gateway는 파일 수준 스토리지를 제공하지만 주로 객체 스토리지 용도로 파일을 Amazon S3에 저장합니다. 파일 시스템 호환성과 성능이 중요한 활성 NFS 워크로드를 마이그레이션하는 데는 적합하지 않습니다. NFS 기반 워크로드를 AWS로 마이그레이션하는 데 가장 적합한 옵션은 Amazon FSx File Gateway입니다.

C. Amazon FSx File Gateway To migrate an NFS (Network File System) on-premises workload to AWS, the company should use the Amazon FSx File Gateway type. Amazon FSx for Windows File Server provides a fully managed Windows file system that is accessible over the industry-standard Server Message Block (SMB) and NFS protocols. Amazon FSx File Gateway allows you to seamlessly integrate an on-premises NFS environment with Amazon FSx for Windows File Server. It enables your existing NFS clients to access an FSx for Windows File Server file system in AWS. The other options are different types of AWS Storage Gateways, but they are not specifically designed for NFS workloads: A. Tape Gateway - Used for archiving data to Amazon S3 or Glacier using virtual tapes, but not designed for NFS workloads. B. Volume Gateway - Provides block storage volumes that can be mounted as iSCSI devices but is not designed for NFS workloads. D. Amazon S3 File Gateway - Integrates an on-premises file system with Amazon S3, but it uses the SMB protocol and is not specifically designed for NFS workloads.
