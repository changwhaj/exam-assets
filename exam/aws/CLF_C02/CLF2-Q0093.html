선택된 답변: C
A. 인프라 변경을 드물게, 그리고 대규모로 수행하여 다운타임을 줄이십시오: 이 내용은 AWS Well-Architected Framework에서 권장하는 모범 사례와 상반됩니다. 일반적으로 인프라 변경은 빈번하고 소규모로 수행하여 문제 발생 위험을 줄이고 시스템의 민첩성을 향상시키는 것이 좋습니다. B. 인프라를 수동으로 구성하는 데 시간을 투자하십시오: AWS Well-Architected Framework는 인프라 구성 및 관리에 자동화를 활용할 것을 권장합니다. 수동 구성은 자동화된 방식에 비해 오류 발생 가능성이 높고, 확장성이 떨어지며, 유지 관리가 어렵습니다. C. 운영 실패로부터 배우고 개선하십시오: 이는 AWS Well-Architected Framework의 핵심 원칙입니다. 실패로부터 배우고 운영 경험을 바탕으로 아키텍처를 지속적으로 개선하는 것의 중요성을 강조합니다. 이를 위해서는 시스템 복원력을 강화하기 위해 실패를 모니터링, 로깅 및 분석하는 메커니즘을 구현해야 합니다. D. 중앙 집중화를 위해 모놀리식 애플리케이션 설계를 사용하십시오: AWS Well-Architected Framework는 일반적으로 모놀리식 설계보다 마이크로서비스 아키텍처를 선호합니다. 마이크로서비스는 모듈성, 확장성 및 유연성을 제공합니다.

Selected Answer: C
A. Reduce downtime by making infrastructure changes infrequently and in large increments: This statement goes against the best practices recommended by the AWS Well-Architected Framework. It's generally recommended to make frequent and smaller changes to infrastructure to reduce the risk of issues and improve overall system agility. B. Invest the time to configure infrastructure manually: The AWS Well-Architected Framework encourages the use of automation to configure and manage infrastructure. Manual configuration is prone to errors, less scalable, and harder to maintain compared to automated approaches. C. Learn to improve from operational failures: This is a key principle of the AWS Well-Architected Framework. It emphasizes the importance of learning from failures and continuously improving the architecture based on operational experiences. This involves implementing mechanisms for monitoring, logging, and analyzing failures to enhance system resilience. D. Use monolithic application design for centralization: The AWS Well-Architected Framework generally favors a microservices architecture over a monolithic design. Microservices promote modularity, scalability, and flexibility.
