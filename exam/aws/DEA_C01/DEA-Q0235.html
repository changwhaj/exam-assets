한 회사가 Amazon Redshift 데이터 웨어하우스를 관리하고 있습니다. 이 데이터 웨어하우스는 사용자 지정 VPC 내의 퍼블릭 서브넷에 있습니다. 보안 그룹은 자체 VPC 내의 트래픽만 허용하고 있으며, ACL은 모든 트래픽에 대해 개방되어 있습니다.

이 회사는 다가오는 영업 행사를 위해 Amazon QuickSight에서 여러 시각화 자료를 생성하려고 합니다. 이를 위해 두 번째 AWS 계정의 두 번째 사용자 지정 VPC 내의 퍼블릭 서브넷에 QuickSight Enterprise 에디션을 실행할 예정입니다. 새 퍼블릭 서브넷에는 기존 Redshift 클러스터로의 아웃바운드 트래픽을 허용하는 보안 그룹이 설정되어 있습니다.

데이터 엔지니어는 Amazon Redshift와 QuickSight 간의 연결을 설정해야 하며, QuickSight는 Redshift 클러스터를 쿼리하여 대시보드를 새로 고쳐야 합니다.

이러한 요구 사항을 충족하는 솔루션은 무엇일까요?

  • A. QuickSight 보안 그룹에서 Redshift 포트로 들어오는 트래픽을 허용하도록 Redshift 보안 그룹을 구성합니다. 가장 많은 표를 받은
  • B. QuickSight 시각화에 탄력적 IP 주소를 할당합니다. 탄력적 IP 주소에서 Redshift 포트로 들어오는 트래픽을 허용하도록 QuickSight 보안 그룹을 구성합니다.
  • C. Redshift VPC와 QuickSight VPC의 CIDR 범위가 동일한지 확인하십시오. CIDR 범위가 다르면 한쪽의 CIDR 범위를 다른 쪽과 일치하도록 재구성하십시오. VPC 간 네트워크 피어링을 설정하십시오.
  • D. Redshift VPC에 QuickSight 게이트웨이 엔드포인트를 생성합니다. 특정 QuickSight 계정만 해당 엔드포인트를 사용할 수 있도록 게이트웨이 엔드포인트에 엔드포인트 정책을 연결합니다.

Question #: 235
Topic #: 1

A company manages an Amazon Redshift data warehouse. The data warehouse is in a public subnet inside a custom VPC. A security group allows only traffic from within itself. An ACL is open to all traffic.

The company wants to generate several visualizations in Amazon QuickSight for an upcoming sales event. The company will run QuickSight Enterprise edition in a second AWS account inside a public subnet within a second custom VPC. The new public subnet has a security group that allows outbound traffic to the existing Redshift cluster.

A data engineer needs to establish connections between Amazon Redshift and QuickSight. QuickSight must refresh dashboards by querying the Redshift cluster.

Which solution will meet these requirements?

  • A. Configure the Redshift security group to allow inbound traffic on the Redshift port from the QuickSight security group. Most Voted
  • B. Assign Elastic IP addresses to the QuickSight visualizations. Configure the QuickSight security group to allow inbound traffic on the Redshift port from the Elastic IP addresses.
  • C. Confirm that the CIDR ranges of the Redshift VPC and the QuickSight VPC are the same. If CIDR ranges are different, reconfigure one CIDR range to match the other. Establish network peering between the VPCs.
  • D. Create a QuickSight gateway endpoint in the Redshift VPC. Attach an endpoint policy to the gateway endpoint to ensure only specific QuickSight accounts can use the endpoint.

Security group referencing allows traffic between resources in different accounts or VPCs, as long as the security groups are configured to allow it. By allowing inbound traffic from the QuickSight security group to the Redshift port (default is 5439), you enable QuickSight to connect securely to Redshift. This approach is simple, secure, and scalable, especially when both resources are in public subnets.
