Question #: 229
Topic #: 1

A company wants to ingest streaming data into an Amazon Redshift data warehouse from an Amazon Managed Streaming for Apache Kafka (Amazon MSK) cluster. A data engineer needs to develop a solution that provides low data access time and that optimizes storage costs.

Which solution will meet these requirements with the LEAST operational overhead?

  • A. Create an external schema that maps to the MSK cluster. Create a materialized view that references the external schema to consume the streaming data from the MSK topic. Most Voted
  • B. Develop an AWS Glue streaming extract, transform, and load (ETL) job to process the incoming data from Amazon MSK. Load the data into Amazon S3. Use Amazon Redshift Spectrum to read the data from Amazon S3.
  • C. Create an external schema that maps to the streaming data source. Create a new Amazon Redshift table that references the external schema.
  • D. Create an Amazon S3 bucket. Ingest the data from Amazon MSK. Create an event-driven AWS Lambda function to load the data from the S3 bucket to a new Amazon Redshift table.

Selected Answer: A
Amazon Redshift Streaming Ingestion allows you to directly query streaming data from sources like Amazon MSK using materialized views, which automatically refresh and keep data up to date. This approach avoids intermediate storage (like S3), reducing latency and storage costs. It’s low-maintenance: no need to manage ETL pipelines or orchestrate jobs—just define the schema and view. B. AWS Glue + S3 + Spectrum: Adds multiple layers (ETL, storage, external query), increasing latency and operational overhead. C. External schema + Redshift table: Redshift tables don’t directly reference external schemas; you’d still need a materialized view or ETL. D. S3 + Lambda: Event-driven Lambda functions require custom code and orchestration, which increases complexity.
