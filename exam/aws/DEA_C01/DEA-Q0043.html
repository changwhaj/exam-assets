주제 번호: 1

한 회사가 AWS Step Functions를 사용하여 데이터 파이프라인을 오케스트레이션합니다. 이 파이프라인은 데이터 소스에서 데이터를 수집하고 Amazon S3 버킷에 저장하는 Amazon EMR 작업으로 구성됩니다. 또한 데이터를 Amazon Redshift에 로드하는 EMR 작업도 포함됩니다.
이 회사의 클라우드 인프라 팀은 Step Functions 상태 머신을 수동으로 구축했습니다. 클라우드 인프라 팀은 EMR 작업을 지원하기 위해 VPC에 EMR 클러스터를 배포했습니다. 그러나 배포된 Step Functions 상태 머신이 EMR 작업을 실행할 수 없습니다.
Step Functions 상태 머신이 EMR 작업을 실행할 수 없는 이유를 파악하기 위해 회사가 취해야 할 조치는 무엇입니까? (두 가지를 선택하십시오.)

  • A. AWS CloudFormation을 사용하여 Step Functions 상태 머신 배포를 자동화합니다. EMR 작업이 실패할 경우 상태 머신을 일시 중지하는 단계를 생성합니다. 해당 단계가 사용자가 이메일 메시지를 통해 승인을 보낼 때까지 기다리도록 구성합니다. 추가 분석을 위해 이메일 메시지에 EMR 작업에 대한 세부 정보를 포함합니다.
  • B. Step Functions 상태 머신 코드가 EMR 작업을 생성하고 실행하는 데 필요한 모든 IAM 권한을 가지고 있는지 확인합니다. 또한 Step Functions 상태 머신 코드가 EMR 작업에서 사용하는 Amazon S3 버킷에 액세스하기 위한 IAM 권한도 포함하고 있는지 확인합니다. S3 액세스 속성을 확인하려면 S3용 액세스 분석기를 사용하십시오. 가장 많은 표를 받은
  • C. 새로 생성된 EMR 클러스터에 대한 Amazon CloudWatch 항목을 확인합니다. AWS Step Functions 상태 머신 코드가 EKS에서 Amazon EMR을 사용하도록 변경합니다. Step Functions 상태 머신 코드에 대한 IAM 액세스 정책 및 보안 그룹 구성을 Amazon Elastic Kubernetes Service(Amazon EKS) 포함을 반영하도록 변경합니다.
  • D. VPC의 흐름 로그를 조회합니다. EMR 클러스터에서 시작된 트래픽이 데이터 공급자에게 성공적으로 도달하는지 확인합니다. Amazon EMR 클러스터에 연결된 보안 그룹이 지정된 포트를 통해 데이터 소스 서버에 대한 연결을 허용하는지 확인합니다. 가장 많은 표를 받은
  • E. 회사에서 EMR 작업에 대해 구성한 재시도 시나리오를 확인하십시오. 각 EMR 작업 간 간격을 초 단위로 늘리십시오. 각 결정 상태에 대해 각 대체 상태에 적절한 예외 처리가 있는지 확인하십시오. 오류 메시지를 저장할 Amazon Simple Notification Service(Amazon SNS) 토픽을 구성하십시오.

Question #: 43
Topic #: 1

A company uses AWS Step Functions to orchestrate a data pipeline. The pipeline consists of Amazon EMR jobs that ingest data from data sources and store the data in an Amazon S3 bucket. The pipeline also includes EMR jobs that load the data to Amazon Redshift.
The company's cloud infrastructure team manually built a Step Functions state machine. The cloud infrastructure team launched an EMR cluster into a VPC to support the EMR jobs. However, the deployed Step Functions state machine is not able to run the EMR jobs.
Which combination of steps should the company take to identify the reason the Step Functions state machine is not able to run the EMR jobs? (Choose two.)

  • A. Use AWS CloudFormation to automate the Step Functions state machine deployment. Create a step to pause the state machine during the EMR jobs that fail. Configure the step to wait for a human user to send approval through an email message. Include details of the EMR task in the email message for further analysis.
  • B. Verify that the Step Functions state machine code has all IAM permissions that are necessary to create and run the EMR jobs. Verify that the Step Functions state machine code also includes IAM permissions to access the Amazon S3 buckets that the EMR jobs use. Use Access Analyzer for S3 to check the S3 access properties. Most Voted
  • C. Check for entries in Amazon CloudWatch for the newly created EMR cluster. Change the AWS Step Functions state machine code to use Amazon EMR on EKS. Change the IAM access policies and the security group configuration for the Step Functions state machine code to reflect inclusion of Amazon Elastic Kubernetes Service (Amazon EKS).
  • D. Query the flow logs for the VPC. Determine whether the traffic that originates from the EMR cluster can successfully reach the data providers. Determine whether any security group that might be attached to the Amazon EMR cluster allows connections to the data source servers on the informed ports. Most Voted
  • E. Check the retry scenarios that the company configured for the EMR jobs. Increase the number of seconds in the interval between each EMR task. Validate that each fallback state has the appropriate catch for each decision state. Configure an Amazon Simple Notification Service (Amazon SNS) topic to store the error messages.
