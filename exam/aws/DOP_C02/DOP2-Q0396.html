DevOps 엔지니어가 관리형 노드 그룹이 포함된 Amazon Elastic Kubernetes Service(Amazon EKS) 클러스터를 성공적으로 생성했습니다. 하지만 클러스터에 노드 그룹을 추가하려고 하면 "NodeCreationFailure: 인스턴스가 Kubernetes 클러스터에 참여하지 못했습니다."라는 오류가 발생합니다.

DevOps 엔지니어는 EC2 워커 노드가 실행 중이고 EKS 클러스터가 활성 상태임을 확인했습니다.

이 문제를 어떻게 해결해야 할까요?

  • A. EKS 클러스터의 VPC 서브넷이 172.17.0.0/16 CIDR 범위와 겹치지 않도록 하십시오.
  • B. kubectl 명령어를 사용하여 클러스터를 생성할 때 사용한 자격 증명을 사용하도록 kubeconfig 파일을 업데이트합니다.
  • C. AWSSupport-TroubleshootEKSWorkerNode 런북을 실행합니다.
  • D. 클러스터용 AWS Identity and Access Management(IAM) OpenID Connect(OIDC) 공급자를 생성합니다.

Exam question from Amazon's AWS Certified DevOps Engineer - Professional DOP-C02
Question #: 396
Topic #: 1

A DevOps engineer successfully creates an Amazon Elastic Kubernetes Service (Amazon EKS) cluster that includes managed node groups. When the DevOps engineer tries to add node groups to the cluster, the cluster returns an error that states, "NodeCreationFailure: Instances failed to join the Kubernetes cluster."

The DevOps engineer confirms that the EC2 worker nodes are running and that the EKS cluster is in an active state.

How should the DevOps engineer troubleshoot this issue?

  • A. Ensure that the EKS cluster's VPC subnets do not overlap with the 172.17.0.0/16 CIDR range.
  • B. Use kubectl to update the kubeconfig file to use the credentials that created the cluster.
  • C. Run the AWSSupport-TroubleshootEKSWorkerNode runbook.
  • D. Create an AWS Identity and Access Management (IAM) OpenID Connect (OIDC) provider for the cluster.

The error NodeCreationFailure: Instances failed to join the Kubernetes cluster is a common but generic error that can be caused by many different issues (networking, IAM permissions, user data configuration, etc.). AWS provides a specific Systems Manager (SSM) Automation runbook called AWSSupport-TroubleshootEKSWorkerNode designed expressly for this situation. This runbook automatically checks the most common causes for worker nodes failing to join the cluster.
