데이터 과학자는 데이터베이스에서 민감한 데이터를 사용해야 합니다. 머신러닝 엔지니어는 원본 데이터를 변환하거나 익명화된 데이터를 데이터베이스에 저장하지 않고도 데이터 과학자가 데이터에 접근할 수 있도록 해야 합니다.

  • A. 동적 데이터 마스킹 정책을 구성하여 쿼리 시 데이터 과학자에게 민감한 데이터가 공유되는 방식을 제어합니다. 가장 많은 표를 받은
  • B. 데이터베이스 위에 마스킹 로직이 적용된 구체화된 뷰를 생성합니다. 데이터 과학자에게 필요한 읽기 권한을 부여합니다.

A company is using an Amazon Redshift database as its single data source. Some of the data is sensitive.
A data scientist needs to use some of the sensitive data from the database. An ML engineer must give the data scientist access to the data without transforming the source data and without storing anonymized data in the database.
Which solution will meet these requirements with the LEAST implementation effort?

  • A. Configure dynamic data masking policies to control how sensitive data is shared with the data scientist at query time. Most Voted
  • B. Create a materialized view with masking logic on top of the database. Grant the necessary read permissions to the data scientist.
  • C. Unload the Amazon Redshift data to Amazon S3. Use Amazon Athena to create schema-on-read with masking logic. Share the view with the data scientist.
  • D. Unload the Amazon Redshift data to Amazon S3. Create an AWS Glue job to anonymize the data. Share the dataset with the data scientist.

The key works here is not duplicating the data which Materialized Views would do for masking. But here's a simple logic for choosing which to use: When to Choose Which: DDM is suitable for: Scenarios requiring simple, role-based masking. When avoiding data duplication is a priority. When the performance impact of real-time masking is acceptable. Materialized Views with Masking Logic are suitable for: Scenarios requiring complex and highly customized masking. When query performance on masked data is critical. When the overhead of managing materialized view refreshes and data duplication is acceptable.
