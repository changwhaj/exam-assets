Topic #: 1

A company has AWS Glue data processing jobs that are orchestrated by an AWS Glue workflow. The AWS Glue jobs can run on a schedule or can be launched manually.
The company is developing pipelines in Amazon SageMaker Pipelines for ML model development. The pipelines will use the output of the AWS Glue jobs during the data processing phase of model development. An ML engineer needs to implement a solution that integrates the AWS Glue jobs with the pipelines.
Which solution will meet these requirements with the LEAST operational overhead?

  • A. Use AWS Step Functions for orchestration of the pipelines and the AWS Glue jobs.
  • B. Use processing steps in SageMaker Pipelines. Configure inputs that point to the Amazon Resource Names (ARNs) of the AWS Glue jobs.
  • C. Use Callback steps in SageMaker Pipelines to start the AWS Glue workflow and to stop the pipelines until the AWS Glue jobs finish running. Most Voted
  • D. Use Amazon EventBridge to invoke the pipelines and the AWS Glue jobs in the desired order.

✅ Explanation: SageMaker Pipelines + AWS Glue Integration Goal: You want SageMaker Pipelines to wait for AWS Glue jobs to finish, since their outputs are needed during the model development phase. You also want to keep operational overhead low. Why Callback steps are the best option: Callback steps in SageMaker Pipelines allow you to pause the pipeline execution until an external process completes. You can: Use the callback step to trigger an AWS Glue workflow (or job). Use a Lambda function or a service like EventBridge or Step Functions to report back to SageMaker when the Glue job completes. This approach provides tight integration while maintaining low operational overhead—you don’t need to build a whole orchestration layer.
