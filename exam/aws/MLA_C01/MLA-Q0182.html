한 회사가 Amazon SageMaker AI 머신러닝 모델을 사용하여 도로 파손으로 인한 교통사고를 예측하고 있습니다. 머신러닝 엔지니어는 SageMaker AI 파이프라인의 일부로 SageMaker Model Monitor를 실행하도록 구성했습니다. MonitoringExecution 출력에서 ​​머신러닝 엔지니어는 파이프라인 실행을 실패하게 하는 여러 baseline_drift_check 위반 사항을 발견했습니다.

이 문제를 해결하려면 머신러닝 엔지니어는 어떻게 해야 할까요?

  • A. 새로운 SageMaker AI 학습 작업을 사용하여 모델을 다시 학습시키십시오. SageMaker 디버거를 사용하여 오류를 확인하십시오.
  • B. 새로운 학습 데이터를 사용하여 모델을 재학습합니다. 모델 모니터에서 원래의 기준선을 재사용합니다.
  • C. 새로운 학습 데이터를 사용하여 모델을 다시 학습시키세요. 모델 모니터에서 새로운 기준선을 사용하세요.
  • D. 기준 제약 조건 파일에서 emit_metrics 옵션을 활성화한 후 SageMaker AI 파이프라인을 다시 실행합니다.

A company is using an Amazon SageMaker AI ML model to predict traffic accidents that potholes cause. An ML engineer has configured SageMaker Model Monitor to run as part of a SageMaker AI pipeline. In the MonitoringExecution output, the ML engineer observes several baseline_drift_check violations that are failing the pipeline.

What should the ML engineer do to resolve this issue?

  • A. Retrain the model by using a new SageMaker AI training job. Check for errors by using SageMaker Debugger.
  • B. Retrain the model with new training data. Reuse the original baseline in Model Monitor.
  • C. Retrain the model with new training data. Use the new baseline in Model Monitor.
  • D. Rerun the SageMaker AI pipeline after enabling the emit_metrics option in the baseline constraints file.

Selected Answer: C
Answer: C — Retrain the model with new training data and use the new baseline in Model Monitor. Why this fixes it A baseline_drift_check violation means the current inference data distribution has shifted away from the original baseline (statistics/constraints) used by SageMaker Model Monitor. To resolve genuine drift, you should refresh the baseline using recent, representative data and retrain (or at least revalidate) the model on updated data so it matches the new distribution. Updating Model Monitor with the new baseline statistics and constraints removes false failures and ensures future monitoring compares against the correct, current state.
