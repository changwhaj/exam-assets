주제 번호: 1

개발팀은 소스 코드에 변경 사항이 발생할 때마다 애플리케이션을 즉시 빌드하고 배포하려고 합니다.

배포를 트리거하는 데 사용할 수 있는 접근 방식에는 어떤 것들이 있을까요? (두 가지를 선택하세요.)

  • A. 소스 코드를 Amazon S3 버킷에 저장합니다. 버킷의 파일이 변경될 때마다 AWS CodePipeline이 시작되도록 구성합니다. 가장 많은 표를 받은
  • B. 소스 코드를 암호화된 Amazon EBS 볼륨에 저장합니다. 해당 볼륨의 파일이 변경될 때마다 AWS CodePipeline이 시작되도록 구성합니다.
  • C. 소스 코드를 AWS CodeCommit 리포지토리에 저장합니다. 리포지토리에 변경 사항이 커밋될 때마다 AWS CodePipeline이 시작되도록 구성합니다. 가장 많은 표를 받은
  • D. 소스 코드를 Amazon S3 버킷에 저장합니다. AWS CodePipeline이 15분마다 시작되도록 구성합니다.
  • E. 소스 코드를 Amazon EC2 인스턴스의 임시 저장소에 저장합니다. 소스 코드에 변경 사항이 있을 때마다 AWS CodePipeline이 시작되도록 인스턴스를 구성합니다.

Topic #: 1

A development team wants to immediately build and deploy an application whenever there is a change to the source code.

Which approaches could be used to trigger the deployment? (Choose two.)

  • A. Store the source code in an Amazon S3 bucket. Configure AWS CodePipeline to start whenever a file in the bucket changes. Most Voted
  • B. Store the source code in an encrypted Amazon EBS volume. Configure AWS CodePipeline to start whenever a file in the volume changes.
  • C. Store the source code in an AWS CodeCommit repository. Configure AWS CodePipeline to start whenever a change is committed to the repository. Most Voted
  • D. Store the source code in an Amazon S3 bucket. Configure AWS CodePipeline to start every 15 minutes.
  • E. Store the source code in an Amazon EC2 instance’s ephemeral storage. Configure the instance to start AWS CodePipeline whenever there are changes to the source code.
