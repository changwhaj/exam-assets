주제 번호: 1

개발자는 AWS Security Token Service(AWS STS)를 사용하는 애플리케이션을 개발했습니다. 이 애플리케이션은 신뢰할 수 있는 사용자에게 임시 보안 자격 증명을 제공하기 위해 STS AssumeRole API 작업을 호출합니다. 애플리케이션은 AWS STS의 기본 엔드포인트인 https://sts.amazonaws.com을 통해 AWS STS를 호출합니다.

애플리케이션은 아시아 태평양 AWS 리전에 배포되어 있습니다. 이 애플리케이션은 AWS STS를 호출할 때 간헐적인 지연과 관련된 오류를 겪고 있습니다.

개발자는 이 문제를 해결하기 위해 무엇을 해야 할까요?

  • A. GetSessionToken API 작업을 사용하도록 애플리케이션을 업데이트하십시오.
  • B. AssumeRoleWithSAML API 작업을 사용하도록 애플리케이션을 업데이트하십시오.
  • C. 애플리케이션 배포 위치와 더 가까운 지역 STS 엔드포인트를 사용하도록 애플리케이션을 업데이트하십시오. 가장 많은 표를 받은
  • D. 애플리케이션을 업데이트하여 AssumeRoleWithWebldentity API 작업을 사용하도록 합니다. STS 엔드포인트를 글로벌 엔드포인트로 이동합니다.

Question #: 523
Topic #: 1

A developer has an application that uses AWS Security Token Service (AWS STS). The application calls the STS AssumeRole API operation to provide trusted users with temporary security credentials. The application calls AWS STS at the service's default endpoint: https://sts.amazonaws.com.

The application is deployed in an Asia Pacific AWS Region. The application is experiencing errors that are related to intermittent latency when the application calls AWS STS.

What should the developer do to resolve this issue?

  • A. Update the application to use the GetSessionToken API operation.
  • B. Update the application to use the AssumeRoleWithSAML API operation.
  • C. Update the application to use a Regional STS endpoint that is closer to the application deployment. Most Voted
  • D. Update the application to use the AssumeRoleWithWebldentity API operation. Move the STS endpoint to a global endpoint.
